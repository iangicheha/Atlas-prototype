# Atlas Benchmark Environments

Atlas retains four warehouse environments for repeatable simulation-based navigation evaluation. The environments are test fixtures, not evidence of measured performance. Benchmark results must be generated by an experiment and recorded with the software configuration, map, planner parameters, and simulator version.

## Environment definitions

| Environment | Objective | Expected challenge |
|---|---|---|
| `benchmark_warehouse_easy` | Basic mapping and navigation validation | Open routes and straightforward turns |
| `benchmark_warehouse_medium` | Validate navigation in a more constrained layout | Tighter aisles and increased clutter |
| `benchmark_warehouse_hard` | Stress replanning and recovery behavior | Tight turns, clutter, and challenging navigation |
| `demo_warehouse_visual` | Demonstrate the integrated system | High-quality visualization and representative warehouse elements |

## Evaluation protocol

A benchmark run should start from a documented initial pose and use a fixed navigation goal or goal sequence. Record the world name, map, robot configuration, sensor toggles, Nav2 parameters, randomization settings, and commit identifier. Repeat each scenario sufficiently to distinguish a stable behavior from a one-off result.

The current repository does not provide an automated benchmark runner or a validated results dataset. The metrics below are therefore **planned evaluation outputs**, not current claims.

## Planned metrics

| Metric | Definition |
|---|---|
| Navigation success | Fraction of goals reached within the configured time and tolerance limits |
| Collision rate | Number of contact or collision events per run, with the event definition documented |
| Path length | Integrated distance traveled by the robot during the run |
| Completion time | Elapsed time from goal dispatch to successful completion or timeout |
| Recovery events | Number and type of Nav2 recovery behaviors invoked |
| Localization stability | Pose and transform quality over the run, including tracking loss or resets |

## Reporting template

For every future benchmark result, report the following:

```text
Environment:
Map:
Goal sequence:
Atlas commit:
ROS 2 / Gazebo versions:
Nav2 configuration:
Sensor configuration:
Runs:
Navigation success:
Collision rate:
Mean path length:
Mean completion time:
Recovery events:

```

No benchmark result should be presented as authoritative until the run configuration and raw observations are retained alongside the summary.
